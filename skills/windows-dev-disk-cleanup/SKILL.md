# Windows 开发机磁盘清理

把清理清单当作发现、用户决策、执行和验收之间的持久合同。完整的发现与执行指引见 [references/windows-cleanup-workflow.md](references/windows-cleanup-workflow.md)。

## 规划和执行必须分开

- 先判断这次请求是只读审计/规划，还是已授权执行。
- 审计或 Plan 模式期间只检查和报告。不要删除文件、清缓存、卸载软件、停进程、改环境变量、关闭 Windows 功能，或安排重启后的工作。
- 只有用户明确授权清单或具名项之后，才开始改动。对已知项的批准，不覆盖后来新发现的候选。
- 以用户最新决定为准。决定一变立刻改清单；若更早的永久删除已经无法撤回，要如实说明。
- 只对真正需要的动作提权。依赖管理员命令前，先核实 administrator / high-integrity 状态。

## 维护清单

- 使用当前工作区根目录的 `清理清单.md`，除非用户指定了别的文件。复用已有清单，不要覆盖它的决策历史。
- 记录磁盘基线、稳定的候选编号、测得或估计的大小、决定、精确边界、前置条件、执行状态、实际空间变化、失败、是否需要重启、以及有意留下的残留。
- 大范围交互分拣时，默认每批问 5 个编号决策，除非用户要求别的批量。每批答完先写入清单，再问下一批。
- 区分 `删除/卸载`、`清理可重建缓存`、`迁移后删除`、`保留`、`待确认`。没有边界的决定不算完整。
- 受保护和明确保留的数据必须一直出现在报告里，避免后续清理阶段把它们悄悄吃掉。

## 安全不变量

- 每个破坏性目标都要落到精确的字面路径、产品标识、包名或功能名。动手前立刻再核所有权和是否仍存在；不要用宽泛 glob，也不要猜目录。
- 优先官方卸载器和所属包管理器。只有对应产品和程序路径已经不在、且能证明该项过期时，才删除卸载注册表项。
- 分别识别缓存、生成依赖、用户配置、凭据、项目、下载和业务数据。名字像，不构成删除许可。
- 拆除旧工具链之前，先建立并验证替换项，例如拆 Conda 之前先有 uv，拆其它运行时之前先确认要保留的 Node/JDK。
- 永远不要删除承载当前智能体或其它活动进程的运行时映像。先钉住并验证要保留的运行时，物理删除推迟到新会话或重启之后。
- 不要把普通磁盘清理扩大到 WinSxS/`ResetBase`、pagefile、WinRE、Windows Update 数据、还原点卷影副本或其它系统组件清理，除非另做单独明确决定。
- 遇到这些情况就停：Windows servicing 正在进行、共享组件关系说不清、要保留的工具验证失败、目标被锁、或现场状态和清单矛盾。

## 执行并验收

- 小阶段推进：基线与替换项、托管卸载、已批准缓存、已批准用户文件、系统设置，然后残留清理。
- 有意义的阶段前后都测量可用空间。目录大小只是估计：硬链接、压缩、包存储、回收站和并发程序都会改变实际腾出的空间。
- 复查要保留的命令、环境变量、仓库、应用路径、注册项、Windows 功能状态，以及待重启标记。
- 除非用户明确授权，否则不要自动重启。把依赖重启的工作和被锁残留记为未完成，不要报成功。
- 结束时用可观察结果更新清单，并删掉仅为这次清理创建的临时脚本或元数据。
