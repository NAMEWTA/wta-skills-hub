## 主要发现与处置

| 发现 | 风险与处置 |
|---|---|
| 单次 curl -4 echo 被用作网络验收 | 改为持久配置、运行时、目标链、echo、真实应用、DNS、IPv6、crash 分层证据 |
| TUN 未验证却关闭系统代理 | 保留原状态；验证接管后才进行授权迁移 |
| 固定 DoH/53 监听及 dns.ipv6=false 的隐含安全假设 | DNS 模板降为最小参考，不自动换解析器/端口；明确原生 IPv6 与 DNS 路由须独立验收 |
| 宽泛品牌关键词、进程 wildcard、无关 DIRECT IP | 最小 DOMAIN-SUFFIX 基线和参数化规则生成；旧用户规则预览迁移，不静默删除 |
| 活动 GUI 文件竞写与未知 SQLite schema | 改为支持的 GUI/导入；必要时正常退出、事务一致备份，未知 schema 停止 |
| POSIX mktemp/chmod 被当成 Windows 通用步骤 | 分平台私有快照/ACL 与原值存在性；PowerShell/WSL/远程明确区分 |
| locale 权限拒绝后建议直接改底层文件 | 删除绕过路径；时区、语言、键盘、浏览器与系统作用域拆开 |
| Windows 系统 locale 生效条件过于笼统 | 单独标出待重启，不承诺重登录即可完成，不自动重启 |
| Mac/Linux 系统健康入口不足 | 新增本地只读、有限成本系统基线和平台审计工作流 |
| Agent/快照/仓库资料可能被当成权限来源 | 增加 AGENTS、宿主权限边界、快照不执行与并发文件边界 |
| 资料与测试来源边界不清 | 三份已读规范附 blob；未核验/错误来源/历史结果明确分离 |

## 测试与待验收

新增 Python 标准库诊断、规则生成与系统基线脚本，离线 unittest 覆盖：默认零联网、显式网络授权、敏感信息隐藏、loopback 限制、拒绝重定向、失败不直连、域名后缀边界、DIRECT/REJECT 区分、证据不足退出码、超大快照、规则字符转义和无系统写入。

开发环境实际运行结果见随交付的验证摘要；CI 新增 macOS，与 Windows/Linux 一起运行。CI 配置存在不等于三个系统已经跑过；PR 检查结果才是 CI 证据。没有用户现场数据，DNS/IPv6、TUN 接管、真实 Claude Code 请求、睡眠/切网与 crash 隔离全部待设备验收。

新的 evals/refactor-cases.json 是待运行的技能选择/行为场景，不是模型评估得分。禁止把单元测试通过写成代理无泄漏或 Agent 选择率提升。

## 现场最小证据包

只分享脱敏 OS/架构、客户端/内核/CLI 版本、启动主机、代理端口类型、模式、单次失败时间、实际目标域名、匹配规则和策略链结论、脚本默认隐藏 IP 的摘要。不要提交订阅、controller 原始连接快照、API key、OAuth 回调 URL 或完整日志。

成功标准不是“美国节点已选”，而是目标流量按期望规则到达已验证的出口，并且需要防直连的范围在故障时满足预先定义的阻断策略。服务地区错误仍可能与 IP 地理数据库、账号资格或服务政策有关，不能由仓库重构承诺解决。
