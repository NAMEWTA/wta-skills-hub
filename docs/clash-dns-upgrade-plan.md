## 目标与不应承诺的结果

目标：受保护业务规则路径正确；内核管理的公网 DNS 使用批准上游且显式经代理；冷启动和订阅刷新不出现解析循环；系统/浏览器解析、原生 IPv6、WebRTC 与异常断线有独立验收；任何变更有明确回滚和隐私降级说明。

不承诺：代理可以改变服务资格；resolver 地理位置等于节点出口；TUN/DoH/fake-ip 开关可以单独保证无泄漏；未连接的用户 Mac 已修复。加密直连的节点 bootstrap 属于可审计例外，不伪装成全部 DNS 走代理。

## 当前缺口

上一版已具备环境/连接/echo 诊断及安全边界，但 DNS 模板只有 `enable: true`，没有参数化的路径固定、bootstrap 计划、策略 map 合并审计、真实 DNS wire 探针或系统/浏览器的事务验收流程。静态安全提示不能替代具体候选和失败用例。

## 自动方案的两个边界

**strict-no-bootstrap：** 全部静态节点地址已经确定，保护组所有候选都不是 DIRECT/REJECT/未知引用，拒绝节点 DNS bootstrap。解析上游为明确批准的公开 numeric DoH/DoT，并显式绑定现有组。存在域名节点（包括其他组）或动态 provider 冷启动依赖时阻止自动候选，避免“改后突然不可用”。

**encrypted-bootstrap-exception：** 用户明确批准 only-node 的加密直连 resolver；其他 DNS 保持经代理。没有批准不自动切换，输出明确不是全部 DNS 经代理。未知 provider 成员、节点地址/协议和组循环仍需解决。私有 provider DNS、域名 DoH、认证 URL 或复杂企业 split DNS 暂不自动渲染，以人工方案和设备验收处理，不用公共 DNS 偷换需求。

现有 DNS policy map 的清空不是简单写 `{}`：递归 Merge 可能保留旧条目。工具要求明确批准替换，给出 `merge_contract`，最终生成配置重新审计。保留未受影响的 listener、端口、filter、stack、MTU、订阅与节点信息。

## 可用性、隐私和回滚门槛

每次只改一个层次；配置保存、内核校验、运行时加载和真实请求分别验证。不会先关已有系统代理、把未监听的 127.0.0.1 写进网卡、删除 Mac DNS 盲等自动接管或默认禁用整机 IPv6。

失败先停止受保护请求和后续改动，再检查回滚是否也存在旧泄漏；恢复旧配置只标记恢复旧行为。LAN/企业 DNS 或音视频受损时不为“隐私检测通过”继续扩大改动。没有本地救援的远程会话不做 crash/防火墙演练。
